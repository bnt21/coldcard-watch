Coldcard Watch

How addresses get tracked

Eight methods run against the chain and against X. Each one keys on a different signal, each proves a different amount, and each is blind to something. The blind spots are the useful column: Wave 3 got through because the first six all key on a funnel, and Wave 3 has no funnel.

The methods

Co-spend co-spend.py, autopilot.py tier 1 Auto-publishes
Keys onTwo addresses signing the same transaction. Walks outward from known attacker addresses through shared inputs.
ProvesCommon ownership, deterministically. One signer held both keys. This is the only test on the project treated as proof.
Blind toAnything unspent. An address that has never signed cannot co-spend, so a fresh vault is invisible until it moves.
Collector fingerprint cluster.py, autopilot.py tier 2 Notify first
Keys onA collector that took many sweeps at one uniform hardcoded fee, all no-change, in a tight block window, with no unrelated history.
ProvesMachine behaviour. Uniformity, not magnitude: 92 of 93 sweeps at exactly 10.0 sat/vB is a script, whatever the absolute fee.
Blind toAny theft without a shared collector. The whole test is a funnel test.
Block scan, single sweeps scan.py Report only
Keys onSeveral one-input, one-output, no-change sweeps landing in the same block, paying the same address at one identical fee rate.
ProvesNothing on its own. It discovers candidates the site was never told about, then freshness-checks each destination.
Blind toBatched sweeps, where one transaction carries many victims. It reads those as a single ordinary spend.
Block scan, batched sweeps scan-batched.py Report only
Keys onMany distinct single-sig segwit inputs, exactly one output, no change, at a fee rate five or more times the block's own median.
ProvesNothing on its own. An owner consolidating produces the same shape, so the fee overpay is the only separator.
Blind toSweeps under its five-input floor, and the second hop. It sees the sweep and stops there.
No-collector, two-hop signer fingerprint wave3.py New, review only
Keys onThe signer, not the destination. Version 2, locktime 0, one nSequence across every input, one output, homogeneous P2WPKH inputs at distinct addresses, no input coin older than block 674,951, then a full no-change forward into a fresh P2WSH that sits unspent.
ProvesThat one piece of software built every transaction in the set. It survives the funnel being deleted, because those fields are what the tool fills in rather than where it sends.
Blind toIntent. This shape is also exactly what Coinkite's advisory told owners to do, so it can rank candidates and can never publish one.

First run over blocks 960396 to 960471 rebuilt 231 chains into 230 vaults holding 203.25 BTC, against Galaxy's 293 vaults and 207.73 BTC, so 97.8% of the value and 78% of the vaults. It found the one Wave 3 chain a third party has published in full. The fee constant reads 200.85 to 201.44 sat/vB rather than the "roughly 200" Galaxy gave, and 215 of the 222 sweeps inside that band went on to terminate in a fresh unspent P2WSH.

Keys onThe same pattern as scan.py, applied to every block since the last run, forever.
ProvesNothing. It converts discovery from something that arrives by tweet into something the chain reports first.
Blind toEverything scan.py is blind to, inherited whole. It reuses that pattern test exactly.
Victim reports on X x-watch.py Auto-publishes when proven
Keys onPeople naming their own drained address. Replies to the tracked threads, quote tweets, links to the site, and a keyword sweep, every 30 minutes.
ProvesThe chain decides, not the tweet. A local Claude call reads the tweet for a claim; verify_addr then checks it.
Blind toVictims who stay quiet, and to anyone who does not yet know. A 1,395-tweet backfill found no unlisted provable victim.
Movement monitor coldcard-watch-monitor.py Telegram
Keys onBalance changes on the addresses already tracked. Runs on the always-on box so it keeps watching with the Mac off.
ProvesThat the coins moved, and where the next hop landed. This is what caught the first attacker movement.
Blind toAny address not already on the list. It watches what is tracked; it does not find anything new.

The publish gate

Detection and publication are separate. Every method above feeds candidates into one tiered gate in autopilot.py, and only two tiers can write to the site.

Tier 1 is co-spend proof. It is deterministic and auto-published, and only when the vault is clean and unspent. A co-spend-proven address whose funds already peeled through further hops is held instead, because tracing where the money sits is a judgement call.

Tier 2 is a fingerprint match plus a credible source. The cluster matches the drain fingerprint and is independently reported by a research account on the watchlist. It is currently gated to notify first (TIER2_AUTOPUBLISH is off) until it is proven on a real case.

Tier 3 is a fingerprint match and nothing else. It is held for a person. A batched sweep at a normal fee is shape-identical to an owner moving to safety, so it gets a Telegram message and never a site edit. The new two-hop detector sits here.

The publish decision is code. claude -p is used only to read a tweet and judge whether a source attributes an address, which is evidence gathering rather than the final say.

Why the shape can never be enough

Coinkite's advisory told every affected owner to generate a new seed, verify a fresh receive address, and move the remaining funds. Following it produces a full drain, no change output, a never-before-seen destination, an urgency fee, and often a two-hop path into multisig. That is the Wave 3 shape.

The population of owners who did this is plausibly larger than the population of victims, so even a low per-transaction error rate yields a candidate list where innocent rescues outnumber thefts. Tightening the fingerprint does not fix that, because it is a base rate rather than a threshold.

Galaxy Research state the same limit on their own work: the pattern tells them the transactions share an attacker, and it does not capture the attack itself, which looks the same as if a coin owner chose to move coins. They also note they have not tested whether the addresses they identify were in fact generated with low entropy. Naming an address as a victim on shape alone is an inference they decline to make, and this project holds the same line.
